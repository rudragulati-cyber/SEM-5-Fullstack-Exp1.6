What This Demo Covers

📄

Pagination

Divides large datasets into pages. Clients request specific pages — reducing bandwidth, server load and memory usage.

GET /api/products?page=2&size=10
🔀

Sorting

Orders results by any field in ascending or descending order — enabling relevance, price, or date-based ordering.

GET /api/products?sortBy=price&direction=asc
⚠️

N+1 Problem

Fetching N products triggers N extra queries for their categories. 10 products = 11 queries. Devastating at scale.

SELECT * FROM products; ← 1 query
SELECT * FROM categories WHERE id=? ← ×N
🔗

JOIN FETCH

Retrieves products and their categories in a single optimized query — eliminating N+1 overhead entirely.

SELECT p, c FROM Product p JOIN FETCH p.category c
🧠

Caching (Ehcache)

Stores query results in memory. Cache HITs skip the database entirely — response times drop from ~30ms to <2ms.

@Cacheable("products")
public Page<Product> getProducts() {…}
🗄️

Native SQL

Complex aggregations (GROUP BY, window functions) that JPQL can't express are written as native SQL for full DB power.

SELECT cat, COUNT(*), AVG(price)
FROM products GROUP BY category_id

SELECT c.name, COUNT(p.id), AVG(p.price), AVG(p.rating), SUM(p.stock)
FROM products p
JOIN categories c ON p.category_id = c.id
GROUP BY c.id, c.name
ORDER BY COUNT(p.id) DESC
